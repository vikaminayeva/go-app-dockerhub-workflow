Автоматизация CI/CD и деплой на Docker Hub через GitHub Actions 🐳

Учебный проект, посвященный настройке полноценного конвейера непрерывной интеграции и доставки (**CI/CD**) для Go-приложения с использованием **GitHub Actions**. В проекте реализован автоматизированный процесс тестирования кода и сборки/публикации Docker-образов на **Docker Hub**.

##  Описание автоматизации (CI/CD Workflow)

Вся логика автоматизации описана в конфигурационном файле `.github/workflows/main.yml`. Конвейер состоит из двух последовательных этапов (**Jobs**), обеспечивающих надежность и стабильность релиза:

### Job 1: Тестирование и проверка (`Lint & Test`)
*   **Триггер:** Запускается автоматически при каждом `push` или `pull_request` в основную ветку.
*   **Действия:**
    1.  Разворачивает изолированное окружение на базе Ubuntu.
    2.  Устанавливает актуальную версию **Go**.
    3.  Скачивает зависимости проекта.
    4.  Запускает автоматическое тестирование (`go test -v ./...`) для проверки корректности работы приложения и слоя базы данных.

### Job 2: Публикация в реестр (`Build & Push to Docker Hub`)
*   **Триггер:** Запускается строго при создании и отправке **тегов версий** (например, `git push origin v1.0.0`).
*   **Действия:**
    1.  Зависит от успешного выполнения первого этапа (`needs: test`).
    2.  Безопасно авторизуется на **Docker Hub**, используя скрытые переменные репозитория (`GitHub Secrets`): `DOCKER_USERNAME` и `DOCKER_PASSWORD`.
    3.  Использует настроенный `Dockerfile` для сборки production-образа.
    4.  Присваивает образу актуальный тег версии и публикует его в публичный репозиторий Docker Hub.

---

##  Безопасность и GitHub Secrets

Для защиты учетных данных авторизация на Docker Hub выполняется через механизм **GitHub Secrets**. В настройках репозитория (*Settings -> Secrets and variables -> Actions*) добавлены защищенные переменные окружения, скрытые от посторонних глаз:
*   `DOCKER_USERNAME` — логин (Docker ID) на Docker Hub.
*   `DOCKER_PASSWORD` — персональный токен доступа (Access Token) или пароль от Docker Hub.

##  Инструкция по использованию и проверке

### 1. Как запустить пайплайн локально
Чтобы инициировать автоматическую сборку и доставку на Docker Hub, достаточно зафиксировать изменения и отправить тег в GitHub:
```bash
# Создаем тег версии
git tag v1.0.0

# Отправляем изменения и тег на GitHub
git push origin main --tags
```

### 2. Как проверить результат
1. Перейдите во вкладку **Actions** в вашем GitHub-репозитории, чтобы увидеть визуальный граф выполнения шагов.
2. После успешного завершения обеих джоб, скачайте и запустите собранный образ из любой точки мира командой:
```bash
docker run --name my-app-release -d ВАШ_DOCKER_ID/go-parcel-tracker:v1.0.0
```
